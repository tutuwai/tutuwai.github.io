# 个人主页文档总览（读我先）

## 1. 这个项目要做什么
做一个用于展示**个人简历（英文）**与**个人项目**的个人主页，并提供明显的 **GitHub 主页入口**。页面风格参考：
- `docs/参考1.png`：简洁分节、左侧信息区 + 右侧正文的学术主页风格
- `docs/参考2.png`：首屏头像 + 角色徽章 + 简洁排版

## 2. 核心决策（已选定）
- **技术路线**：Astro（静态站点）
- **部署平台**：GitHub Pages（GitHub Actions 自动发布）
- **页面形态（MVP）**：单页 + 顶部导航锚点（About / Projects / Resume / Contact）
- **内容语言**：\n  - 计划/文档：中文\n  - 主页正文（个人介绍/项目描述/简历）：英文

## 3. MVP 范围（最小可交付）
- About：英文自我介绍 + 头像 + 徽章 + GitHub/邮箱等链接
- Projects：项目卡片/列表（至少 3 个项目，含 GitHub 链接与技术栈标签）
- Resume：网页简历要点（可选附 PDF）
- Contact：联系方式
- 响应式 + 基础 SEO + 可部署到 GitHub Pages

## 4. 文档地图（建议阅读顺序）
1. `docs/01_需求说明(PRD).md`\n   - 定义目标、范围、验收标准
2. `docs/02_信息架构与内容清单.md`\n   - 站点结构与“中文字段说明模板（内容填英文）”、项目数据结构
3. `docs/03_技术路线_Astro.md`\n   - 为什么用 Astro、推荐目录结构与扩展点
4. `docs/04_部署指南_GitHub_Pages.md`\n   - GitHub Pages 部署、`site/base`、Actions 工作流与排查清单

## 5. 开工建议（最省时间的顺序）
- 先完成内容（Phase 0）：\n  - 按 `docs/02_信息架构与内容清单.md` 把英文内容填好\n  - 把项目清单整理成 JSON/Markdown（先 JSON 更快）
- 再做页面（Phase 1）：\n  - 先把单页结构搭出来（4 个 section）\n  - 再做 ProjectCard 与 Badge 组件\n  - 最后补 SEO 与响应式细节
- 最后部署：按 `docs/04_部署指南_GitHub_Pages.md` 配置 `site/base` 与 Actions

## 6. 里程碑
- Phase 0（内容准备）：英文 About + 项目字段齐全（链接/标签/亮点）
- Phase 1（MVP 上线）：单页完成 + 项目展示 + GitHub Pages 可访问 URL
- Phase 2（增强）：项目详情页/博客/多语言/统计分析/自定义域名

## 7. 验收口径（MVP 快速检查）
- 首屏可见 GitHub 链接与英文定位
- Projects 至少 3 个项目且每个有 GitHub 链接与 tech tags
- 移动端/桌面端均无明显排版问题
- 已部署到 GitHub Pages，push 可自动更新
